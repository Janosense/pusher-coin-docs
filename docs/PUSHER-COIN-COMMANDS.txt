Pusher Coin — Home Assistant API reference
==========================================

The pusher machine is exposed through a Home Assistant instance at
https://developer-it.com/api. All calls require a long-lived bearer
token in the Authorization header.

DO NOT commit a real token to this file. The live token must live in
`wp-config.php` as a PHP constant `PC_MACHINE_TOKEN` so it stays out of
the repository, backups, and admin UI. The MachineService PHP class
(backend/wp-content/themes/pc/app/utils/machine-service.php) reads it
from there at runtime.

If you need to rotate the token, generate a new one from the HA
profile page (Long-Lived Access Tokens) and update the constant in
wp-config.php. Revoke the old token in the same screen.

Entity IDs (operator-tunable WP options; defaults shown):

still carry the old device id). Verified against the live instance during the

NOTE 2026-09-18: what the machine actually reports, observed in the realtime
Sprint 1 Step 2 spike (DECISIONS.md 2026-09-18 "Spike: machine events reach
WordPress by polling Home Assistant's history"). The lines further down, and the
defaults table, are left as they were; the table still shows the code's defaults,
which later realtime steps change.
  - sensor.coin counts the coins paid out since the last toss. A press of
    input_button.toss_a_coin resets it to 0 within about 2 s. It rises in steps
    on a ~2 s Modbus cycle, sometimes several at once, and is 0 after every
    power-on. It is not a running total.
  - sensor.relay_on reflects the relay the buttons below switch: about 1.1 s
    after input_button.relay_off it reads 0, and after input_button.relay_on it
    reads 1. Its normal state is 1 ("closed", by the button names). It does
    not change during payouts.
  - sensor.sw_b_t_relay (not listed below) exists and stayed 0 for ten days,
    including while the relay was switched.
  - sensor.lc01_12 was 0 in every reading over ten days: no bonus was seen.
  - Unchanged values are never re-reported (last_reported always equals
    last_updated), so the same value written twice leaves no trace.
  - With the power off, the sensors read "unavailable" after about 3.5 min; after
    power-on they come back as one batch 9-45 s later.

The headers used by every call below:

    headers = {
        "Authorization": "Bearer <your-long-lived-access-token>",
        "Content-Type": "application/json"
    }

----------------------------------------------------------------------

Включить питание автомата:
response = requests.post(
        "https://developer-it.com/api/services/switch/turn_on",
        headers=headers,
        json={"entity_id": "switch.s60tpf"}
    )

Выключить питание автомата:
response = requests.post(
        "https://developer-it.com/api/services/switch/turn_off",
        headers=headers,
        json={"entity_id": "switch.s60tpf"}
    )

Бросить монетку:
response = requests.post(
        "https://developer-it.com/api/services/input_button/press",
        headers=headers,
        json={"entity_id": "input_button.toss_a_coin"}
    )

Сколько монет выпало:
response = requests.get("https://developer-it.com/api/states/sensor.coin", headers=headers)
data = response.json()
print(f"Состояние {ENTITY_ID}: {data['state']}")

Какое число засветилось на круговом табло:
response = requests.get("https://developer-it.com/api/states/sensor.lc01_12", headers=headers)
data = response.json()
print(f"Состояние {ENTITY_ID}: {data['state']}")
